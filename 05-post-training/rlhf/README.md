# RLHF：让模型从反馈里继续学

**中文** · [English](README.en.md)

> 阅读时间：约 2 分钟 · 难度：必修 · 最近审阅：2026-10

你问“第一次学 Python，今天可以做点什么？”一个回答讲了半页语言发展史，另一个带你写几行代码，马上试一下。两段都可能没什么事实错误，但对于这个问题，后者更有用。

这样的差别，很难全写成标准答案。让人比较两份回答，往往容易一些：哪份更贴题，哪份漏了重要信息，哪份只是在凑字数。

RLHF 想利用的就是这类反馈，让模型在预训练和 SFT 之后继续调整回答方式。

## 反馈怎么变成训练信号？

经典做法先收集人的比较，再训练一个 Reward Model 去预测这些偏好。之后让语言模型自己生成回答，用奖励模型给分，再用 RL 更新它。

```text
人比较回答 → 学会预测偏好 → 模型生成新回答 → 根据评分更新
```

这里最值得留意的是中间那一步：训练时直接优化的是奖励模型的分数。如果它误把“长”当成“好”，模型可能越来越啰嗦，而不是越来越有用。所以训练结束后，还得另外检查回答质量。

这条路线的公开实例见 [InstructGPT](https://arxiv.org/abs/2203.02155)。后面的 GRPO、DPO 等方法会改动其中一些环节，我们会分开看。

## 读到后面，会遇到哪些名字？

真正生成回答、需要改进的模型叫 **Actor**。Reward Model 给结果打分；**Critic** 估计从当前前缀继续写，通常能拿多少回报；**Reference** 保留一份参照策略，帮助衡量模型改了多少。

第一次读不必一次记住这几个角色。先跟着一条回答看它怎么生成、怎么得到反馈，再回头看各自为什么需要。
