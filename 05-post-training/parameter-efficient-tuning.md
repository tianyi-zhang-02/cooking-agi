# Prompt、Prefix、Adapter：冻结模型后，还能改哪里？

**中文** · [English](parameter-efficient-tuning.en.md)

> 最近审阅：2026-10 · 前置：[模型适配](model-adaptation.md)、[LoRA / QLoRA](lora-and-qlora.md)

还是让现有模型把客服记录整理成固定格式。这次保持数据和损失函数不变，只比较允许哪些参数变化，看看把可训练参数放在不同位置会有什么影响。如果连训练任务也一起换了，就很难判断差异来自哪里。

参数高效微调（parameter-efficient fine-tuning，PEFT）是一类只更新少量参数的方法，而不是一种损失函数。它既可以用于监督微调，也可以用于其他训练目标。下面几种方法都会冻结模型的大部分或全部原有参数，但梯度仍可能需要穿过这些冻结部分。

## 先画出四个可以动的位置

```text

每层注意力：[可学习的前缀键／值] + [文本的键／值]
层内表示：  h → 小型非线性适配器 → h'

```

图中最后一种就是 LoRA，即低秩适配。这张图只说明四种方法从哪里改变计算；实际插入位置、参数是否共享，以及参数如何表示，都要看具体实现，不能只凭方法名判断训练了什么。

## Prompt Tuning：在输入前学一小段向量

提示微调把一组可学习向量放在文本输入之前。设模型宽度为 $d$，这组向量包含 $m$ 个位置，记为 $P\in\mathbb R^{m\times d}$：

$$
H_0=[P;E(x)],\qquad \hat y=f_{\theta_0}(H_0).
$$

这里 $E(x)$ 是文本的嵌入向量序列，$[P;E(x)]$ 表示沿序列方向拼接，$\theta_0$ 是冻结的模型参数。训练只更新 $P$。这组向量称为软提示（soft prompt），通常不能逐个对应到可读的词，因此不同于人写的一段提示词。机制见 [Prompt Tuning（2021）第 2 节](https://arxiv.org/abs/2104.08691)。

取 $m=16,d=512$，这组软提示有 8,192 个参数。但模型仍要处理这些额外位置，梯度仍要从输出传回输入。可训练参数减少，并不代表中间激活值占用的显存也按相同比例缩小。

推理时，在使用因果注意力的解码器中，若模型权重、软提示和位置处理都固定，软提示的部分状态可以预计算。具体能缓存什么仍取决于任务和实现，而且缓存并不消除这些位置占用的上下文长度与后续注意力计算。训练时软提示持续更新，不能把旧状态直接跨参数更新复用。

## Prefix Tuning：在每层提供额外的 Key / Value

前缀微调可以简化为：在每层直接学习 $m$ 对额外的键和值，记为 $K_P,V_P$，供文本位置的查询 $Q$ 使用：

$$
\operatorname{Attn}\left(Q,[K_P;K_x],[V_P;V_x]\right).
$$

其中 $K_x,V_x$ 来自文本本身。文本位置的查询可以关注前缀位置，因此这不只是在输入前添加向量，而是直接在每层提供额外的注意力键和值。[Prefix-Tuning（2021）第 4.3 节](https://arxiv.org/abs/2101.00190)还使用额外网络生成前缀；训练结束后，可以只保存生成的前缀状态。所以，最终状态的大小不一定等于训练时的参数总量。

若有 $L=6$ 层、$m=16$，且每层键和值各自的总宽度都是 $d=512$，直接存储的前缀包含 $2Lmd=98,304$ 个标量。若使用分组查询注意力，多个查询头共享键和值，就应代入实际的键值宽度，而不能直接用查询的总宽度计算。

这些虚拟位置不需要产生普通的输出预测，但仍会参与注意力计算、占用键值缓存。做实验时，除了学习率，也应比较初始化、前缀长度，以及各层前缀参数的组织方式。

## Adapter：在层内加一条非线性小支路

瓶颈适配器先把层内表示压到较低维度，再映回原来的宽度。省略偏置后，一种常见形式是：

$$
h'=h+W_{\mathrm{up}}\phi(W_{\mathrm{down}}h),
$$

其中 $r$ 是瓶颈宽度，$W_{\mathrm{down}}\in\mathbb R^{r\times d}$，$W_{\mathrm{up}}\in\mathbb R^{d\times r}$，$\phi$ 是非线性激活函数。输入先降维、经过非线性变换，再升维并加回原输入。[Houlsby 等人（2019）第 2 节](https://arxiv.org/abs/1902.00751)介绍了这种适配器，具体放置位置可以随实现变化。

不计偏置，单个模块需要 $2dr$ 个参数。$d=512,r=8$ 时是 8,192 个。因为中间有非线性变换，通常不能像线性 LoRA 增量那样直接合并进原矩阵，推理时会多一段计算。

瓶颈太窄可能限制表达能力；每层都插入适配器则会增加开销。把模块初始化成近似恒等映射，可以让训练从接近原模型的行为开始。不过，在上面无偏置且 $\phi(0)=0$ 的设定下，把两块矩阵都设成零会让这条分支的参数梯度也为零。初始化后仍需检查它能否收到有效梯度。

## 同一小模型，四种方法的账怎样列？

仍取 $L=6,d=512,m=16,r=8$。下表计算的是这些明确约定下的参数量或状态大小，不比较任务效果：

| 方法 | 本例约定 | 可训练参数 / 状态规模 |
| --- | --- | ---: |
| 提示微调 | 输入处一组 $m\times d$ 向量 | 8,192 |
| 前缀微调 | 每层直接学习键和值，各自总宽度为 $d$ | 98,304 |
| 瓶颈适配器 | 每层 1 个瓶颈模块，不计偏置 | 49,152 |
| LoRA | 每层只改一个 $d\times d$ 矩阵 | 49,152 |

适配器一行是教学算例，不是 Houlsby 原论文的完整配置：原论文每层插入两个适配器，还训练层归一化参数和任务分类头。本表只计每层一个无偏置模块，没有计入这些额外参数。

这里适配器与 LoRA 的参数量相同，不代表能表示的函数相同。若把 LoRA 加到注意力的查询、键、值、输出投影，以及前馈网络的多个矩阵中，参数会更多；比较时必须列出实际加入 LoRA 的目标模块。

## 冻结权重后，梯度为什么还要穿过模型？

软提示位于模型输入端，损失 $\mathcal L$ 则由模型输出计算。要得到 $\partial\mathcal L/\partial P$，必须沿中间的计算应用链式法则。如果把整个模型放进 `no_grad()`，通常也就切断了这条路径。冻结权重应当阻止这些权重更新，而不是切断从损失回到软提示的计算图。

瓶颈适配器和 LoRA 的训练，同样可能需要梯度穿过周围的运算。实现时可以不保存反向传播用不到的中间量，也可以用梯度检查点重算部分结果，但节省多少取决于计算图的结构，详见[精度与显存](../00-foundations/deep-dives/precision-and-memory.md)。

## 选择之前，先做一个公平的小实验

固定数据、训练目标、分词器、训练词元总数和调参预算。相同的调参预算不等于共用同一个学习率：各方法应在同样的预算内分别调优。记录任务质量、通用能力是否退化、可训练参数量、峰值训练显存、推理延迟，以及每个任务需要额外保存的参数大小。

如果任务只是按固定格式输出，先用精心设计的普通提示词做对照；如果需要大幅改变能力或学习大量领域知识，就不能假定极小的适配器一定够用。部署多个任务时，还要检查切换适配参数后旧缓存能否继续使用、不同任务能否一起批处理，以及基础模型与适配参数的版本是否匹配。

选择时应看需要改变的行为、合适的更新位置，以及实测节省的资源。每个任务保存的文件最小，不代表整体方案最合适。
