# 对齐税：变听话之后失去了什么

**中文** · [English](alignment-tax.en.md)

> 阅读时间：约 7 分钟 · 类型：教学 · 最近审阅：2026-08

## 对齐改变的是能力分布

对齐不是免费的。你换来的是更符合偏好的单次输出，付出去的是**分布的宽度**——模型在同一个问题上还能给出多少种不同的好答案。而这笔账在任何一个平均分上都看不出来，因为**平均分只看一次采样，而你失去的是第二次采样本可以不一样**。

## 这笔税具体长什么样

**输出多样性下降。** 同一个提示采样多次，对齐后的模型给出的回答彼此更像。这是最直接、也最容易量的一项。

**熵坍塌。** 训练过程中策略分布逐渐变尖，低概率 token 越来越难被选中。[算法那篇](after-ppo.md)讲过一个机制性原因：PPO 的对称裁剪对当前概率很低的 token 只允许极小的绝对提升，它几乎没有翻身机会。DAPO 的 Clip-Higher 就是冲着这个来的。

**塌到"安全回答"。** 如果偏好数据里稳妥的回答系统性地更受偏好，那么最优策略就是**永远给稳妥回答**。模型学会了一种"万金油体"：结构工整、免责声明齐备、信息密度低。

**过度拒绝。** 无害性训练的边界不可能划得刚好，而拒绝的代价通常低于说错的代价，于是策略会把边界往安全一侧偏移。

## 为什么这几乎是必然的

不是实现没做好，是目标函数决定的。

RL 优化的是**期望回报**。而对一个给定提示，期望回报的最优解通常是**一个点，不是一个分布**——如果奖励模型认为风格 A 比风格 B 好哪怕一点点，那么"永远输出 A"就严格优于"有时 A 有时 B"。

$$\pi^* = \arg\max_\pi \mathbb{E}_{y \sim \pi}[r(x,y)]$$

这个式子里没有任何一项在奖励多样性。**多样性不是被牺牲掉的，是从来没有被要求过。**

SFT 不太有这个问题，因为交叉熵是在拟合一个分布——数据里有多少种写法，模型就学多少种。RL 是在爬一个标量的坡。

这也是 KL 惩罚的第二层作用：它不只是把策略约束在[奖励模型还算数的区域](where-preferences-come-from.md)，也顺带拖住了分布收窄的速度。**但它是价格调节旋钮，不是安全开关**——调大保住了多样性，同时也拿不到对齐收益。

## 但这是权衡，不是纯损失

得说另一半，否则这篇就成了反对对齐的檄文。

有研究发现，和 SFT 相比，**RLHF 在分布外输入上的泛化更好**，尤其当测试分布和训练分布差得远的时候。所以这笔交易的真实形状是：

> **用分布的宽度，换分布外的稳健。**

这就解释了为什么两边都有道理："RLHF 让模型变笨了"和"RLHF 让模型好用多了"可以同时为真——**它们量的是不同的东西**，前者量宽度，后者量单次命中。

真正的错误不是做了这个交易，是**做了却没有量过价格**。

## 怎么量：一个总分永远看不出来

关键在于：**多样性的损失只在多次采样时才可见。**

**pass@k 与 pass@1 的裂口。** 这是最硬的一条判据。

- pass@1 涨、pass@k 也涨 → 模型真的变强了；
- **pass@1 涨、pass@k 掉 → 你把分布压成了点。**

第二种情况里，模型只是把原本分散在 k 次采样中的正确答案集中到了第一次。**总能力没有增加，只是采样效率提高了**——而这在只报 pass@1 的评测里看起来是纯粹的进步。

对需要多次尝试的场景（agent 重试、best-of-n、测试时扩展），这是真实的损失：**你把 best-of-n 的原料给砍了。**

其余可以量的：

| 量什么 | 怎么量 |
| --- | --- |
| 词汇多样性 | 同一提示多次采样的 distinct-n / n-gram 熵 |
| 语义多样性 | 采样两两之间的嵌入相似度（self-BLEU 的向量版） |
| 分布尖锐度 | 生成时的平均 token 熵，逐训练步记录 |
| 拒绝率 | 在一个明确无害的对照集上测，专门抓过度拒绝 |
| 长度漂移 | 平均输出长度随训练步的曲线 |

**熵和长度这两条要按训练步画曲线，不是训完测一次。** 坍塌是渐进的，只有曲线能告诉你它是什么时候开始的、以及是不是还能停下来。

## 一个实践上的建议

在训练开始之前，先在基座模型上把上面这些量测一遍，**存成一条基线**。

对齐税只能通过与训练前的基线比较来测量。等到发现输出变得千篇一律时，那个基线往往已经不存在了：checkpoint 被清理，或者评估配置已经改变，无法再做有效比较。

这与[冻结评估配置](../07-evaluation/)是同一件事：**先保留稳定的测量基线，才谈得上改进。**

## 评估对齐效果时检查什么

1. 我报的是 pass@1 还是 pass@k？两者的裂口在往哪个方向走？
2. 我有基座模型的多样性基线吗？还是只有对齐后的数字？
3. 生成熵随训练步是什么曲线？有没有单调下降到某个平台？
4. 我的输出长度在训练中是不是单调变长？如果是，是内容变多还是话变密？
5. 我有没有一个"明确无害"的对照集专门测过度拒绝？
6. 我的 KL 系数是根据什么定的——是量出来的，还是抄来的？
