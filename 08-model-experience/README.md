# 模型体验：用得久了，它真的更好用吗？

**中文** · [English](README.en.md)

## 先看连续用下来的感受

这里说的模型体验，不只是某次回答写得好不好。更想问的是：它还记得前面的事吗？能听懂纠正吗？关键决定能由我来控制吗？用得久了，是否真的更省心？

## 用户感受到的是连续使用过程

两个助手都能正确回答“帮我规划一周健身”。

助手 A 每次都重新问你的目标、器械和伤病情况。

助手 B 记得你的膝盖曾经受伤，但在使用这条信息前会确认它是否仍然有效；当计划不合适时，它能记住你的修改，而不是下次继续犯同样的错。

单次 benchmark 上，两者可能得分接近。长期体验却完全不同。

## 具体看哪些方面

### 有用：有没有真正完成任务

不只是语言通顺，而是结果能否执行、能否减少用户工作。

### 相关：是否理解这次想做什么

同一个用户在不同时间可能有完全不同的目标。长期偏好不能覆盖当前任务。

### 有选择：会不会总是推荐同一类东西

推荐的内容可能越来越符合已知偏好，却也越来越少出现新主题和新选择。

### 可控：用户能不能纠正和干预

用户应该能查看、修改记忆，确认高风险行动，并知道系统为什么这样做。

### 不乱下结论：信息不足时能否说清楚

证据不足时，追问或承认不确定通常比自信生成更好。

### 连贯：换一次对话，还能不能接着聊

模型不该今天记住一件事，明天就完全忘掉；也不该只凭一次偶然行为，就认定你一直如此。

## 为什么单轮评估不够

有些问题得连续用上几轮，甚至几周，才会发现：

- 错误记忆不断被重复使用；
- 用户已经纠正，系统却没有更新；
- 每轮回答都不错，但整体目标逐渐偏移；
- 个性化越来越窄；
- 工具失败后，系统假装任务完成。

所以除了测单次问答，还要做会话级评估，看看几轮对话能否完成任务；也要做纵向评估，观察多次使用后问题是否得到解决。

## 离线指标怎样连接体验

Recall、NDCG、judge score、task success 都有用，但每个指标只看见一部分。

更完整的评估可以组合：

- 任务完成率和可执行验证；
- 相关性、覆盖率和多样性；
- 用户纠正次数和重复解释成本；
- 记忆更新与撤回是否成功；
- 工具和行动的实际结果；
- 多次使用后的满意度，以及用户怎样依赖这个助手。
