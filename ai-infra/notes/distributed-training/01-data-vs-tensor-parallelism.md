# 数据并行和张量并行，到底切的是什么？

**中文** · [English](01-data-vs-tensor-parallelism.en.md) · [返回 AI Infra](../../README.md)

> 阅读时间：约 5 分钟 · 难度：Beginner · 时效性：Stable · 最近审阅：2026-09

## 核心问题

DP（Data Parallelism）和 TP（Tensor Parallelism）经常被并列提起，但它们切分的是训练里完全不同的东西：DP 复制模型、切分数据；TP 复制数据、切分模型内部的矩阵运算。分不清这一点，就很难理解为什么两者要组合使用，也算不出一个模型该先用哪一个。

## DP：每张卡都有完整模型

```text
GPU0: 完整模型 + batch 的一部分
GPU1: 完整模型 + batch 的另一部分
```

每个 rank 拿到不同的一份数据，独立做 forward/backward，得到自己的梯度，再用 AllReduce 把所有 rank 的梯度求平均，最后各自用同一份梯度更新参数。因为起点相同、梯度相同，更新后每张卡的参数仍然保持一致。

DP 几乎不需要改模型代码，只要能把 batch 切开、把梯度同步好。代价是：**每张卡都要放下完整的参数、梯度和优化器状态**——模型一旦大到单卡装不下，纯 DP 就会失败，这也是 FSDP2/ZeRO 要把这三者也切分开的原因。

## TP：一次矩阵乘法被拆到多张卡上

以一个线性层 `Y = XW` 为例，把权重 `W` 按列切成两半 `[W1 | W2]`，分别放在两张卡上：

```text
GPU0: Y1 = X · W1
GPU1: Y2 = X · W2
```

每张卡各自算出输出的一部分，再用 AllGather（列切分场景）或 AllReduce（行切分场景）把结果拼起来，才能继续下一层。也就是说：**同一个样本、同一次矩阵乘法，被拆成了两次更小的矩阵乘法**，卡与卡之间必须频繁通信才能对齐中间结果。

这也是 TP 和 DP 最大的行为差异：DP 的通信只发生在一个 step 结束、梯度同步的时候；TP 的通信发生在**每一层内部**，因为下一层需要上一层完整的输出。所以 TP 通常只在高带宽互联（比如同机 NVLink）的卡之间使用，跨节点做 TP 代价很高。

## 一张表对比

| | DP | TP |
| --- | --- | --- |
| 切分对象 | 数据（batch） | 模型内部的矩阵/张量 |
| 每卡是否有完整参数 | 是 | 否，只有分片 |
| 通信时机 | 每个 step 一次（梯度） | 每一层内部多次（激活） |
| 典型原语 | AllReduce | AllReduce / AllGather |
| 对拓扑的敏感度 | 较低 | 高，通常要求高带宽互联 |
| 解决的问题 | 用更多样本加速训练 | 单层放不下单卡 |

DP 和 TP 不是互斥的：现实中的大模型训练通常把两者叠在同一个 device mesh 上——同机内几张卡做 TP，跨机再做 DP，各自应对不同层面的容量和带宽约束。

## 关键计算

判断纯 DP 是否够用，先看参数能不能放进单卡：

```text
单卡所需显存 ≈ 参数 + 梯度 + 优化器状态 + activation
```

用 FP32 Adam 训练时，参数、梯度、一阶矩、二阶矩各占一份，大致是 `4 × 参数量 × 4 字节`（不含 activation）。一旦这个数字超过单卡显存，纯 DP 就撑不住，需要引入 TP、FSDP2 或两者组合。

## 动手验证

1. 用两张 GPU 跑一个小模型的 DDP，打印每个 rank 更新前后的参数，确认梯度同步后两边完全一致。
2. 手写一个把线性层权重按列切到两张卡的小例子，验证拼接后的输出和单卡结果一致。
3. 分别统计 DP 和 TP 版本中，一个 step 里发生了几次通信、每次传输多大。

## 常见误区

- 以为 TP 也像 DP 一样只在 step 末尾同步一次——实际上 TP 的通信在层内部，频率高得多；
- 以为用了 TP 就不再需要 DP——多数大规模训练仍然需要 DP（或其变体）跨节点扩展吞吐；
- 只看「切了几份」就当作显存已经解决——activation、通信 buffer 等仍要单独核算。
