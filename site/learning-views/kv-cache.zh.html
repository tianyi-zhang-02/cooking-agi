输入是 A、B、C。模型先处理整段输入，预测出 D；下一步把 D 喂进去，再预测 E。

01

留下前面的 K、V

A、B、C 的 Key 和 Value 已经算过，可以缓存起来。它们不是之前生成的文字，而是每一层算出的向量。

02

下一步只算新来的 D

给 D 算新的 Q、K、V，把新的 K、V 接到缓存后，再计算 D 这一行 attention。旧 token 的 K、V 不用重算，但 D 仍要关注整个前缀。

03

少算一点，多存一点

上下文越长，缓存通常越大。算得更少不代表一定快同样的倍数：读缓存、搬数据和其他层也要花时间。

一个容易混的细节

刚预测出 D 时，缓存里只有 A、B、C。等下一步真正把 D 输入模型，才会得到 D 的 K、V。

什么情况下能复用？

这里讨论因果 decoder 的推理：模型权重、前缀和位置设置不变，dropout 关闭。不是所有 attention 都能照搬这套缓存。

这些数字在数什么？

按单层、单个 attention head 计数，前缀长度为 t。不缓存时，有效因果 attention score 是 t(t+1)/2 个；缓存后，新 token 只需算一行，共 t 个。这里不是 FLOPs 或速度测试，也没有把其他层的成本算进去。
