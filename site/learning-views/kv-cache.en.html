Start with just three tokens

The input is A, B, C. The model processes that prefix and predicts D. Next, it takes D as input to predict E.

ABC
→D
01

Keep the earlier keys and values

The keys and values for A, B, C have already been computed. Cache those vectors at each layer—not just the text that was generated.

02

Compute only the new token, D

Compute Q, K, V for D. Its query attends to the cached keys and its new key. The earlier keys and values are reused, but D still attends to the whole prefix.

03

Less computation, more memory

A longer context generally means a larger cache. Less work does not translate directly to the same speedup: reading the cache, moving data, and running other layers still take time.

One detail worth catching

Right after predicting D, the cache only contains A, B, C. D gets its own keys and values when it is fed into the model on the next step.

When can we reuse it?

This example uses a causal decoder at inference time, with unchanged weights, prefix, and position settings, and dropout off. The same cache strategy does not apply to every attention pattern.

What are we counting?

Counts are per layer and attention head, for a prefix of length t. Without a cache, causal attention has t(t+1)/2 valid scores. With a cache, the new token needs just one row of t scores. These are not FLOP counts or measured speedups, and do not include the other layers.
