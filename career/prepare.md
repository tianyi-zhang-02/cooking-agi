# 求职：到底要准备什么

**中文** · [English](prepare.en.md)

> 阅读时间：约 4 分钟 · 最近审阅：2026-10

刚开始准备时，最头疼的是不知道该准备到什么程度。LeetCode、ML 基础、系统设计、论文、项目，随便打开一个都能看很久。

去年我的范围铺得太大，拿到面试才发现又得补一块。现在回头看，如果让我重新安排，会先做下面这些事。不是一张必须照做的课表，只是按我自己的短板排的。

## 先弄清楚自己投的是什么

我会先找几份真的想投的 JD，看看它们反复在问什么，而不是看到 MLE 这个名字就默认准备内容一样。

建模、数据、训练、上线维护，各个组需要的比重可能差很多。自己更想做哪部分，已经有什么经历能接上，缺的又是什么，先有个大概。地点、毕业时间、工作许可这些也一起看，免得准备很久才发现条件对不上。

不需要第一天就定下一辈子的方向。先选一个主要方向准备，其他感兴趣的留着了解，比全部同时开始更适合我。

## 简历上写过的，先能讲明白

我以前容易把“做过”和“能讲清楚”当成一回事。真被追问时，才发现中间还差一遍整理。

如果是一个项目，我会拿着简历上的那条，试着不看稿讲几分钟：当时遇到了什么问题，我负责哪部分，为什么选这个做法，最后实际做到了哪里。

讲着讲着卡住的地方，往往就是要回去补的地方。比如：

- 说的是“我们做了”，但自己的那部分没分清楚。
- 记得用了什么模型，解释不出为什么不用另一个。
- 报得出一个指标，却没说比较对象、数据和评估条件。
- 把提出的设计、已经实现的部分和真正验证过的结果混在一起。

有数字当然好，没有就把交付物和证据说具体。不能因为简历需要一个漂亮结果，就把还没测的写成已经提升。做得不顺的地方也可以讲，尤其是当时怎么发现问题、后来为什么换了思路。

## 基本功要练，但得看自己卡在哪

对我来说，刷过题不代表下次能写出来，学过一个模型也不代表能解释它。准备时得留一点时间真的动手、真的开口，不能一直停在看答案。

想练算法，可以去 [LeetCode 方法](../interview/leetcode.md)；想过 ML 和系统设计，可以从[技术学习入口](../interview/README.md)和[系统设计](../interview/system-design.md)挑。这里不再列一遍所有知识点。

我会更愿意固定留一小段时间，复习之前卡住的东西，而不是等拿到面试再全部重看。要是近期主要面研究相关岗位，也得给论文和项目追问留时间，不能把准备全变成刷题。

还有一个我自己容易忽略的事：我大部分技术知识是用英文学的。要面中文，就得真的用中文讲几遍。脑子里知道英文词，临场不一定能顺畅地换过来。

## 有些东西，问人比继续搜快

岗位每天到底在做什么，JD 有时写得很宽。能和做这类工作的人聊一下，会比继续猜有用。可以具体问：新人一般接什么任务？这个组偏实验还是偏工程？自己现有的经历能不能接上？

内推也可以问，但我不想把认识的人都变成找工作的渠道。对方愿意抽时间回答，或者帮忙看简历，已经很感谢了。说清楚自己的情况，也别把“帮忙递了简历”理解成对方能保证结果。

## 第一次听到这些词时

放个小表，省得来回搜。这里只解释常见用法，具体安排还是看招聘方怎么说。

| 词 | 我会怎么理解 |
| --- | --- |
| OA | Online Assessment，线上测评，可能是编程题或其他测试 |
| recruiter screen | 和 recruiter 沟通经历、意向和时间线等基本情况 |
| phone / technical screen | 技术筛选轮；名字和形式不一定完全对应 |
| onsite / loop | 一组面试，不一定真的去现场 |
| BQ / behavioral | 聊过去怎么处理具体事情，通常需要真实例子 |
| system design | 给定需求和约束，讨论系统怎么设计、为什么这样选 |
| HC | 多半指 headcount（招聘名额），有时指 hiring committee（招聘委员会），要看上下文 |
| team match | 和具体团队沟通匹配情况；在流程中的位置各家不同 |
| level | 职级，对应的职责和预期需要单独了解 |
| base / bonus / RSU / sign-on | 底薪、奖金、限制性股票单位、签字费；不是每份 offer 都有这几项 |
| refresh | 入职后追加的股权授予；有没有、何时发，要看具体安排 |
| return offer | 实习后继续回公司工作的 offer；回去做什么、何时开始，以实际条款为准 |
| referral | 内推，可以帮助转交申请或提供推荐，但不保证面试或录用 |
| ATS | Applicant Tracking System，管理申请和招聘流程的系统；简历最好保持清楚、易读取 |

## 面完以后，再改准备计划

我会建议趁还记得，留几句很具体的记录：哪个概念没答出来，哪段项目讲太久，代码到底卡在思路还是实现。自己的例子在[这篇复盘](one-interview.md)。

不用每次都写成长文，也不用每次面完就把计划推倒重来。如果连续几场都卡在同一个地方，那块就值得多花时间；如果只是一次没接住，先补上就好。

真没状态的时候也可以歇一下。不用按“挂几场就休息几天”给自己再定一条规则，自己已经累到看不进去时，硬坐着也未必有用。

准备和投递可以一起走。我不想再等到觉得什么都会了才开始投，因为大概率等不到；但也不想把每个新岗位都当成必须立刻补完一个新领域的理由。
