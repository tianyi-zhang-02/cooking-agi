# 求职：一次 MLE 面试的复盘

**中文** · [English](one-interview.en.md)

> 阅读时间：约 3 分钟 · 最近审阅：2026-09

> **先读这个**：很多内容有时效性，你读到的时候或许已经不适用了；我是 international student，所以这些经验对有绿卡或者 US citizen 的同学不一定完全适用；这里不写面试题，也不写任何一家公司特定的面试流程。完整说明见[求职：先读这一页](README.md)。

刚从实习回来，最近开始准备找全职。这是一场刚面完的 MLE 面试，趁热写的复盘。

很多信息我模糊掉了，也希望你不要过拟合：我面过挺多岗位，每家要求都不太一样；人的精力有限，做不到尽善尽美是常事，别太焦虑。

## 我的起点

硕士 New Grad。去年找实习时刷过一些 LeetCode，但 ML 八股和 system design 一直是弱项，LeetCode 也只能算一般，ML coding 更是没怎么系统练过。

和我之前面过的一些美国 tech 公司比，这家更看重 ML 基础知识和项目经历，整体是一次比较 generalized、standardized 的面试。面试官人很好，我卡住的时候给了不少提示。

## 前半场：聊项目

聊的是实习里做的推荐系统 retrieval。我花了些时间讲这几件事：

- 项目具体做了什么；
- 为什么这么设计；
- 当时面对哪些系统和 serving 约束；
- 模型训练里的资源配置和计算成本取舍；
- 我自己在实验中的观察和思考；
- 为什么最后选了这套兼顾效果和线上 serving 成本的架构。

面试官也问了项目有没有上线，我如实说了最终的交付范围，没有上线。

## 中间：一个没接住的问题

聊到最近比较火的某个方向，我提了我们探索时遇到的问题，以及为什么在当时的系统约束和项目周期里没走这条路。面试官说，他们在自己的业务场景下已经有对应的方案了。

我当时愣了一下，没能马上组织好回答。后来复盘，更合适的回应应该是：我并不觉得这条路不可行，只是各家的数据分布、系统架构、计算预算、latency、freshness、serving 要求都不一样，适用的方案自然不同——如果当时能反过来追问他们是怎么处理这些 trade-off 的，这段讨论会有价值得多。

## 后半场：ML 八股

之前没面过国内大厂，只听说会更看重基础知识和项目。这轮的 breadth 确实比我面过的一些美国 tech 公司更广，传统 ML 模型也在考察范围里。

然后毫无悬念，我拉垮了（笑）。不少东西以前确实学过，但平时做的方向比较集中，临场没顺利调出来。面试官一直在给提示，也辛苦他了。

这轮最大的复盘：**如果准备国内大厂的 MLE，ML 八股要认真、全面地过一遍**，不能只准备和自己当前项目最相关的那部分，传统 ML 这些基础仍然可能被广泛考到。

项目那部分我的体会是：只要能把问题、设计依据、系统约束和 trade-off 讲清楚，言之有理就行。

## 还有一件事：语言

我的 coding 和 ML 知识体系基本都是用英文学的，这次技术部分主要用中文交流，一些术语要临场在中英文之间转换，表达上有些卡顿。这不是主要原因，但确实是之后要专门练的地方。

## 小结

这个岗位和我的经历不算特别 match，加上准备不足，表现拉垮确实没什么借口，接下来继续沉淀。

我面了两个 RS 岗位，后面会继续更新。总体来说，我觉得心态调整是最重要的。
