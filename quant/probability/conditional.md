## 条件概率：把世界缩小到 A

**定义**（这是定义，不是定理）：当 $P(A) > 0$，

$$P(B \mid A) = \frac{P(A \cap B)}{P(A)}$$

可以这样理解：已经知道 A 发生了，A 以外的结果就都不用考虑了，A 成了新的样本空间。B 在这个范围里剩下的部分是 $A \cap B$；再除以 $P(A)$，是为了让新样本空间的总概率重新等于 1。

在下面这张图里，整个方块是 Ω，面积代表概率。切换到「已知 A 发生」后，A 会被拉伸到铺满整个框；B 在新框里占的比例，就是 $P(B \mid A)$。

## 链式法则：永远成立

把定义挪一下：

$$P(A \cap B) = P(A)\,P(B \mid A)$$

这条式子**总是成立**，不需要额外假设。两个事件相关时也可以这样乘，只是第二项要用条件概率。

以下雨和下雪为例：$P(\text{下雨且下雪}) = P(\text{下雨}) \cdot P(\text{下雪} \mid \text{下雨})$。如果下雨的日子更容易下雪，结果就会比 $P(\text{下雨}) \cdot P(\text{下雪})$ 大。

## 独立：条件概率塌缩成普通概率

**定义**：$P(A \cap B) = P(A)\,P(B)$。它和 $P(B \mid A) = P(B)$ 是同一句话的两种写法：

- 如果 $P(A \cap B) = P(A)P(B)$，代进条件概率的定义，$P(B \mid A) = P(A)P(B) / P(A) = P(B)$；
- 反过来，$P(B \mid A) = P(B)$ 两边乘上 $P(A)$，就回到 $P(A \cap B) = P(A)P(B)$。

反过来同样有 $P(A \mid B) = P(A)$。所以，独立可以看成链式法则的一个特例：条件概率恰好等于原来的概率。

一个常见误解是：**「能同时发生」不等于独立。** 下雨和下雪可以在同一天发生，但它们多半是相关的，因为都受同一个天气系统影响。有交集是独立的必要条件，但不是充分条件。独立要靠计算验证，不能凭感觉判断两件事有没有关系。实际题目里，独立通常来自题目的设定，比如两枚不同的硬币、两个不同的日子，而不是看集合的形状。

## 互斥不是独立

这是概率面试里最常见的错误之一。

| | 互斥（disjoint） | 独立（independent） |
| --- | --- | --- |
| 说的是 | 集合：$A \cap B = \varnothing$ | 概率：$P(A \cap B) = P(A)P(B)$ |
| 意思 | A 发生了，B 就不可能 | 知道 A 发生，对 B 没有任何信息 |
| 配哪条法则 | 加法：$P(A \cup B) = P(A) + P(B)$ | 乘法：$P(A \cap B) = P(A)P(B)$ |

要记住的一点是：**如果两个事件的概率都大于 0，它们互斥就一定不独立。** 互斥意味着 $P(A \cap B) = 0$，独立却要求 $P(A \cap B) = P(A)P(B) > 0$，两者矛盾。互斥其实是一种很强的相关：知道 A 发生了，就知道 B 不可能发生。

掷一颗骰子，三个例子：

- $A = \{1, 2\}$，$B = \{5, 6\}$：互斥。$P(B \mid A) = 0$，可 $P(B) = 1/3$，不独立。
- $A = \text{偶数} = \{2, 4, 6\}$，$B = \text{不超过 4} = \{1, 2, 3, 4\}$：有交集。$P(A) = 1/2$，$P(B) = 2/3$，$P(A \cap B) = P(\{2, 4\}) = 1/3 = 1/2 \times 2/3$，所以独立。不过这只是数字恰好对上了，判断时一定要把 $P(A \cap B)$ 算出来。
- A 和 $A^c$：互斥。除非 $P(A)$ 是 0 或 1，否则不独立。

## 全概率公式

按 A 发生和不发生分成两种情况，分别乘上各自的概率，再加起来：

$$P(B) = P(B \mid A)\,P(A) + P(B \mid A^c)\,P(A^c)$$

不知道 A 有没有发生、又想求 B 的概率时，就可以用它。

## 贝叶斯：把条件反过来

已知 $P(B \mid A)$，想求 $P(A \mid B)$，就用贝叶斯公式。它就是把链式法则从两个方向各写一遍，分母用全概率展开：

$$P(A \mid B) = \frac{P(B \mid A)\,P(A)}{P(B \mid A)\,P(A) + P(B \mid A^c)\,P(A^c)}$$

最经典的例子是检测。某种病的患病率是 1%；检测对患者有 99% 的概率报阳性，对健康人也有 5% 的概率误报阳性。一个人检测阳性，他真的患病的概率是多少？

用人数来想最直观。假设有 10000 人：100 人患病，其中 99 人检测阳性；9900 人健康，其中 495 人被误报阳性。阳性一共 594 人，真正患病的只有 99 人：

$$P(\text{患病} \mid \text{阳性}) = \frac{99}{99 + 495} = \frac{1}{6} \approx 17\%$$

检测本身很准，结果却只有六分之一，原因是病太少见：健康人基数大，5% 的误报加起来比真阳性还多。这就是「基础比率」的作用，很多人会直觉地回答 99%。

## 两两独立不等于相互独立

掷两枚均匀硬币：A = 第一枚正面，B = 第二枚正面，C = 两枚一样。

- $P(A) = P(B) = P(C) = 1/2$；
- $P(A \cap B) = P(A \cap C) = P(B \cap C) = 1/4$，所以三对都独立；
- 但 $P(A \cap B \cap C) = P(\{HH\}) = 1/4 \ne 1/8 = P(A)P(B)P(C)$，三个一起**不**相互独立。

原因是只要知道其中任意两个，第三个也就确定了。这是「两两独立但不相互独立」的经典例子，面试里经常出现。

## 面试常见问题

<details class="interview" markdown="1">
<summary>掷两枚硬币，A = 第一枚正面，B = 第二枚正面，C = 两枚一样。A 和 B 互斥吗？独立吗？A 和 C 呢？</summary>

A 和 B 不互斥（HH 两个都满足），独立：$P(A \cap B) = 1/4 = 1/2 \times 1/2$。A 和 C 也不互斥，$A \cap C = \{HH\}$，$P(A \cap C) = 1/4 = P(A)P(C)$，同样独立。三个放一起见上面：两两独立，但不相互独立。

</details>

<details class="interview" markdown="1">
<summary>不放回地抽两张牌，A = 第一张是 A，B = 第二张是 A。求 P(A ∩ B)、P(B)，A 和 B 独立吗？放回呢？</summary>

不放回：链式法则，$P(A \cap B) = \frac{4}{52} \cdot \frac{3}{51} = \frac{1}{221}$。全概率，$P(B) = \frac{3}{51} \cdot \frac{4}{52} + \frac{4}{51} \cdot \frac{48}{52} = \frac{1}{13}$。而 $P(A)P(B) = \frac{1}{169} \ne \frac{1}{221}$，不独立。

意外的是 $P(B) = 1/13$，和第一张一模一样：不知道第一张是什么的时候，第二张和第一张是对称的。

放回：$P(A \cap B) = \frac{1}{169}$，$P(B) = \frac{1}{13}$，独立。

</details>

<details class="interview" markdown="1">
<summary>一家有两个孩子，已知至少有一个是男孩，两个都是男孩的概率是多少？如果已知老大是男孩呢？</summary>

假设男女各一半、两个孩子相互独立，$\Omega = \{BB, BG, GB, GG\}$，四种等可能。「至少一个男孩」是 $\{BB, BG, GB\}$，所以 $P(BB \mid \text{至少一个男孩}) = 1/3$。「老大是男孩」是 $\{BB, BG\}$，这时答案是 $1/2$。两个问题的区别在于条件划出来的样本空间不一样。

</details>

<details class="interview" markdown="1">
<summary>互斥和独立有什么区别？两个互斥事件能独立吗？</summary>

互斥说的是集合：$A \cap B = \varnothing$，配加法；独立说的是概率：$P(A \cap B) = P(A)P(B)$，配乘法。两个概率都为正的互斥事件一定不独立——互斥让 $P(A \cap B) = 0$，独立要求它等于一个正数。

</details>

<details class="interview" markdown="1">
<summary>为什么 P(A ∩ B) = P(A)P(B) 和 P(B | A) = P(B) 是一回事？</summary>

用条件概率的定义 $P(B \mid A) = P(A \cap B) / P(A)$：前者代进去得到后者；后者两边乘 $P(A)$ 得到前者（需要 $P(A) > 0$）。

</details>
