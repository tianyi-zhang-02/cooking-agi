# Agents：用 frontier API 还是自己 serve

**中文** · [English](model-choice.en.md)

> 阅读时间：约 2 分钟 · 难度：进阶 · 最近审阅：2026-09

## 先看能力够不够

agent 的错误会沿着步骤累积。如果每一步独立地有 95% 的概率做对，20 步全对的概率只有

$$0.95^{20} \approx 0.36$$

单步差那么一点，放到长任务里就被放得很大。所以先在**自己的任务**上测一遍：开源模型够不够用？不够，后面那些因素都不用谈。

## 几个维度一起看

| 维度 | Frontier API | 自己 serve（开源权重） |
| --- | --- | --- |
| 能力上限 | 通常更高，长任务和复杂规划尤其明显 | 看选哪个模型，窄任务上往往够用 |
| 成本结构 | 按 token 付费，量小的时候便宜 | GPU 和人力是固定开销，量大又稳定才划算 |
| 延迟 | 看网络和服务商当时的负载 | batch 和部署位置都能自己调 |
| 数据与合规 | 数据得发给服务商 | 数据不出自己的环境 |
| 定制 | 主要靠 prompt，有些支持微调 | 可以拿自己的数据微调、做 RL |
| 版本控制 | 什么时候更新、什么时候下线，服务商说了算 | 自己决定什么时候换 |
| 运维负担 | 几乎没有 | 推理框架、扩缩容、监控全得自己扛 |

## 成本怎么算

agent 很吃 token：一个任务动辄几次到几十次模型调用，而且每一步都要把越来越长的上下文重发一遍。下面这张图可以填自己的数字——API 的成本随 token 线性地长；自己 serve 则有一块固定的底（全天开着的 GPU，加上维护它的人），一组副本装不下了才往上跳一级。

## 不是二选一：混着用

大多数系统最后都不是「全用 A」或「全用 B」，而是同一批流量分给两个模型。四种花钱方式：

<!-- widget:tx-model-router -->

- **级联**：小模型先答，拿不准的再升级给 frontier。FrugalGPT（2023）研究的就是这个。
  代价是被升级的那条请求付了两遍钱。
- **路由**：先判断难度，再决定派给谁，一条请求只付一次。RouteLLM（2024）训了一个这样的路由器。
  但它在看到答案之前就下注，猜错了没人接住。
- **蒸馏**：拿 frontier 在某个量大又固定的窄任务上跑出轨迹，微调一个自己 serve 得起的小模型。
- **兜底**：自己的模型处理常见情况，异常再交给 frontier。

上面那张图里真正决定成败的是「难度判断的准头」。判断准，级联和路由都很划算；
判断接近瞎猜，两个中间方案都不如挑一个模型做简单点——多出来的那层只是在增加故障面。

## 成本之外的三件事

**延迟是串起来的。** agent 一个任务要调好几次模型，用户感受到的是这几次之和。
首 token 时间（TTFT）和每 token 时间要分开看：短回答受 TTFT 主导，长回答受后者主导。
自己 serve 能把 batch、显卡型号、部署位置都调了，API 只能等。

**上下文是成本大头。** agent 每一步都要把越来越长的历史重发一遍，所以花的钱大致随步数平方涨。
prompt caching（把不变的前缀缓存下来）在这里省得最多；能不能缓存、缓存多久，是选服务商时该问的。

**模型会变。** API 背后的模型会更新、会下线，同一个 prompt 过几个月给出的答案可能不一样。
自己 serve 的权重不会自己变——代价是安全更新也得自己跟。两种情况都需要一套回归测试，
把「上周还好好的」这件事测出来。

## 自己 serve 的成本到底由什么决定

不是「买几张卡」这么简单，真正吃成本的是利用率：

- **并发与批处理**：一张卡同时处理的请求越多，摊到每条上的成本越低。流量有波峰波谷，
  按峰值买卡、按均值用卡，中间那段就是白付的。
- **KV cache 占显存**：长上下文的 agent 尤其明显，显存先于算力成为瓶颈，能同时跑的请求就少了。
  vLLM 的 PagedAttention 和 SGLang 的 RadixAttention 都是在解这个问题。
- **人**：推理框架升级、扩缩容、监控、值班。这一项在小团队里往往比 GPU 还贵。

## 一个决策顺序

1. 数据能不能离开自己的环境？不能，就只能自己部署。
2. 在自己的评估集上，开源模型达不达标？不达标，就用 frontier 模型。
3. 流量是不是又大又稳定？是，自己 serve 的成本优势才会出现。
4. 需不需要在自己的数据上微调或做 RL？需要，就更倾向开源权重。
5. 都还说不准，就先用 API 上线，把质量和成本测出来，再回头算这笔账。
