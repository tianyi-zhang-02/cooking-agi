# Looped Transformer：代价与局限

**中文** · [English](costs.en.md)

> 阅读时间：约 5 分钟 · 难度：进阶 · 最近审阅：2026-10-09

## 计算和延迟：圈数是串行的

固定每圈工作量时，循环块的计算量随圈数增加；输入层、输出层等固定成本要另算。同一个位置后一圈依赖前一圈，不能直接同时计算。调度器可以穿插独立请求，提高利用率，但不会消除这个数据依赖。端到端延迟还受 batch、访存和排队影响，不一定严格按圈数成倍增长。

## KV cache 随圈数增长

权重共享，不代表各圈的 K/V 相同：投影收到的隐藏状态已经变了。若要保留完整的逐圈历史，缓存需要区分（圈，层）。以 24 层、4 圈、每个 K/V 宽度 2048、BF16 为例：

$$\text{bytes/token}=2\times24\times4\times2048\times2=786{,}432$$

这里前一个 2 表示 K 和 V，后一个 2 是每元素字节数。结果为 768 KiB，即约 0.786 MB；单条 4096-token 序列就是 3 GiB。这个账不包含模型权重、临时 activation、allocator 和服务预留，也不能套给 GQA 的 KV 宽度。

## 能不能各圈共享 KV

可以研究，但共享通常改变原来的计算，而不是等价的存储压缩。看报告时，要区分 checkpoint、prefill 是否共享、decode 共享规则和输出长度：

- [Ouro](https://arxiv.org/abs/2510.25741)报告了一些 decode-only 共享设置下较小的质量变化；这里减少的是相应 decode KV，不是整张卡的所有显存。
- [Continuous Depth Batching](https://arxiv.org/abs/2608.09444)（2026）表 1：Ouro 的 GSM8K-CoT 完整缓存 / 单槽共享 / 首圈独立分别为 77.86 / 0.23 / 71.34；Huginn 在该全深度设置为 33.74 / 33.97 / 34.80。协议不同，不是严格相同设置的直接反证。该文吞吐实验回放预先记录的长度与退出决策，也要与独立的质量评估分开看。
- [MELT](https://arxiv.org/abs/2605.07721)（2026）表 5 的免训练共享基线严重退化，**不是 MELT 方法本身全得 0**；其主方法加入缓存机制和后训练，再评估质量。不同生成长度和格式可能放大缓存误差。
- [Mixture-of-Recursions](https://arxiv.org/abs/2507.10524)比较按圈稀疏存储与跨圈共享，效果依路由方案而变；不能忽略跳过 token 后还剩哪些 keys 可用。
- [Huginn](https://arxiv.org/abs/2502.05171)研究过循环槽位复用，但实验表现不等于数学等价，更不能推出其他模型也适用。

最小验证可以先固定 prompt 和解码，比较 full-cache 与共享版的 logits，再看短答案、长推理和峰值内存。没有逐位一致，就明确把它当近似方案，讨论误差与收益。

## 训练更难

更深的反传链可能带来梯度和显存问题，但不必然不稳定。完整反传中，共享权重会接收各次使用的梯度；截断反传省下激活，却改变梯度。Input injection 提供持续访问输入的路径，也不是普适的稳定性保证。

## 别把知识容量实验当成定理 {#_3}

Ouro 的约 2 bit/parameter 来自指定合成数据与训练协议，不是所有神经网络的统一上限。循环不新增权重，但训练质量、编码方式、外部记忆和输入信息都会影响能答出多少知识。应把参数存储、从上下文取用事实、对事实继续推理分开评估。

## 什么时候值得

- 权重存储受限，且能接受额外计算；仍需确认 KV 没有成为新瓶颈。
- 在目标任务上，多圈比少圈确有收益，并且没有明显伤害其他任务。
- 能用同一预算比较 dense、looped、CoT 或检索方案，而不是只按参数大小挑模型。
