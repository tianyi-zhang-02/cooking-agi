# 表征与记忆：模型应该怎样“记住一个人”？

**中文** · [English](README.en.md)

## 先用一句话讲清楚

记忆不是把所有历史都存下来，而是让模型在需要的时候，能够找到**仍然相关、来源清楚、并且允许被新证据修改的信息**。

## 一个最简单的例子

用户半年前说过自己不喝咖啡，今天却开始研究手冲。

一个粗糙的系统可能会：

- 永远记住“不喝咖啡”，继续过滤所有咖啡内容；
- 或者只看今天的行为，立刻认为用户已经变成咖啡爱好者。

更好的系统应该保留时间和不确定性：

```text
长期状态：过去通常不喝咖啡
当前意图：最近正在主动了解手冲
置信度：兴趣可能正在变化，暂时不要下永久结论
证据：三次搜索 + 一次明确提问
```

这就是为什么 Personal AGI 需要的是**可修正的用户状态**，而不是一份静态个人档案。

## 表征和记忆有什么区别

- **表征（representation）**：此刻怎样把信息编码成模型可以使用的形式。
- **记忆（memory）**：哪些信息跨时间保留，以及以后怎样被读出、更新和遗忘。

表征回答“现在怎样描述”，记忆回答“以后还要不要相信”。

## 可以把记忆分成几层

### 工作记忆

当前任务正在使用的上下文。例如刚刚的对话、打开的文件和本轮工具结果。容量小，但需要非常精确。

### 情景记忆

过去具体发生过什么。例如用户上周规划了一次东京旅行。它保留事件和时间，不急着概括成永久偏好。

### 语义记忆

从多次事件中提炼出的相对稳定事实。例如用户通常使用 Python，或者长期住在某个时区。

### 偏好与目标状态

用户喜欢什么、正在追求什么，以及这些判断的证据和置信度。它往往会变化，也可能互相冲突。

### 程序性记忆

系统学会怎样与这个用户合作。例如对方喜欢先看结论，还是喜欢完整推导。

## 记忆系统真正需要解决的四个动作

### 写入

不是每句话都值得成为长期记忆。系统要判断信息是否稳定、是否与未来任务有关、是否经过用户确认，以及保存是否合适。

### 读取

记忆很多时，关键变成“当前任务应该取出哪一部分”。这本质上也是一个 Search 问题。

### 更新

新证据不一定直接覆盖旧信息。系统需要保留变化过程、来源和置信度，而不是只存最后一个值。

### 遗忘

过期、错误、敏感或不再有用的信息应该被删除、降权或停止调用。不会忘记的系统并不一定更聪明。

## 为什么一个向量可能不够

一个人可能同时喜欢机器学习、旅行、摇滚和动物。把所有历史压成一个向量，主流兴趣可能会盖住小众但真实的需求。

所以可以考虑：

- 多个兴趣向量，而不是一个平均点；
- profile、长期历史和当前 session 分开编码；
- 用 routing / gating 决定本次任务调用哪部分状态；
- 保存证据与时间，让表示可以被解释和修正。

重点并不是“向量越多越好”，而是表示是否保留了任务真正需要的差异。

## 怎样知道记忆做得好不好

不能只测“有没有召回过去的信息”，还要看：

- 取出的记忆是否真的帮助当前任务；
- 错误记忆会不会持续污染后续回答；
- 用户纠正后，系统是否真的更新；
- 多次 session 后是否变得更有帮助，而不是越来越狭窄；
- 系统是否能解释某个判断来自哪些证据。
