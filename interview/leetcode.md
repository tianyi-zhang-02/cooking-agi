# 技术面：LeetCode 怎么刷

**中文** · [English](leetcode.en.md)

> 阅读时间：约 2 分钟 · 最近审阅：2026-09

> **先读这个**：面试的形式和重点变得很快，这里的内容有时效性；这里只写我自己的刷题方法，不写任何一家公司的面试题或流程。

先说结论：**算法题没有捷径，该刷就得刷。** 也没有什么独门学习方法可以分享——网上有很多 guide 和教程，做得比我好。这一篇只是我自己的做法，供参考。

## 刷什么

- **Hot 100 / 150**：最省事的起点，覆盖了绝大多数常见题型。
- **公司 tag 的题**：临近面试时按公司标签刷，性价比很高。

要不要开会员、要不要多准备，我觉得看个人需求。我的态度是多多益善，有时间就做做。

## 刷到什么程度

LeetCode 更像一个**硬性测试**：达标就行 :)

除非你是竞赛出身，否则没必要在算法题上追求尽善尽美——它和实际工作的关联其实不大。把时间留一些给项目、系统设计和基础知识。

我自己的难度分布大概是一个 bell shape：

- **medium 做得最多**，这是主战场；
- **easy 主要用来学题型**，medium 会了之后，easy 基本能秒；
- **hard 刷得比较少**，学起来时间长，也费脑子哈哈。

## 我的方法

很简单，一个题型一个题型地刷：

1. 挑一个题型，连着做这一类的题；
2. 不会就**先看别人的 implementation**，抄一遍，把它理解掉；
3. 过一阵**回过头再做一次**，这次自己写；
4. 有想不明白的地方，让 ChatGPT 或者 Claude 老师给你讲一遍，比死磕快得多。

关键是第 3 步。只看懂不算会，隔几天能自己写出来才算。

用 Python 刷的话，先把[刷题用得上的 Python 语法](python.md)过一遍，能省不少时间。

## 题型清单

按这个顺序一类一类过，差不多就覆盖到了：

- 数组、双指针、滑动窗口
- 哈希表、前缀和
- 二分查找
- 排序与区间问题
- 链表
- 栈与队列（含单调栈）
- 二叉树与递归
- BFS / DFS 与图
- 回溯
- 动态规划
- 贪心
- 堆 / 优先队列
- 字符串

## 一句话

它是一道门槛，不是一场修行。达标之后，把精力放回真正决定你能做什么的地方。
