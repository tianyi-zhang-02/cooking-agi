# 系统设计：同一个问题，不只一种答案

**中文** · [English](README.en.md)

每道题先给出需求和限制。你可以先设计一个简单可用的版本，再改几个条件，看看原来的方案哪里需要调整。不用追求画出一张“标准架构图”。

以下题目都是**自拟的教学练习**，不是任何公司的面试原题，也不代表线上生产配置。

## 先选一道题

| 题目 | 主要练什么 | 最容易漏掉的事 |
| --- | --- | --- |
| [推荐 Feed](feed.md) | 召回、排序、新鲜度与降级 | 被召回漏掉的内容，排序救不回来 |
| [带引用的知识库问答](rag.md) | 索引、检索、权限与证据 | “看见了文档”不等于“答案有依据” |
| [可更正的长期记忆](memory.md) | 写入、冲突、检索与删除 | 用户改了信息，旧版本仍可能被取出 |

## 每题怎么练

先花 5 分钟写清要解决什么、暂时不做什么，以及时间、成本等限制。再画数据流，标出每一步传递的信息。最后想一个出错的场景：服务超时、信息过期、数据分布变了，或者用户撤回权限，原来的设计还能正常工作吗？

方案不一定越复杂越好。如果去掉一个组件也能满足需求，就没必要为了架构图好看而留着它。

## 设计题和项目拆解有什么区别

设计题允许你声明假设、比较方案；[工程实践](../../practice/README.md)要求你回到公开资料，说明真实代码里采用了什么、哪些仍然看不见。两边会互相链接，但不能把自己设计的图说成别人线上的事实。
