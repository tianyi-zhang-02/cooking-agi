# 后训练实践：从一个具体错误开始

**中文** · [English](README.en.md)

> 原创教学项目 · 最近核验：2026-10。使用合成样本和 loss 数值，不声称运行了完整 SFT / RL 训练。

助手找到了正确资料，回答里的日期也没错，却经常不写出处。这时可以改提示、加输出格式约束，也可以考虑训练。怎么选，要先看问题出在哪里：**它没拿到信息，还是拿到以后没有按要求使用？**

这里接着用 RAG 知识库助手，重点放在后训练。每天变化的规则适合通过检索更新；“回答时引用证据”“资料冲突时说明冲突”这些较稳定的行为，则可以考虑用示范来教。

## 从一个能检查的失败开始

先给模型当前规则，明确要求返回答案和引用。收集它漏写引用的输入，看看改提示或限制输出格式能否解决。如果在各种问法下都能稳定做到，就可以先不训练；如果依然反复出错，再准备有针对性的示范。

| 观察到的问题 | 先做什么 | 什么时候考虑训练 |
| --- | --- | --- |
| 回答的是旧规定 | 查检索快照和证据 | 行为修正不能代替更新知识 |
| 有证据，但总是漏格式 | 清楚提示、结构化输出约束 | 对多种表达仍不稳定，需要学习一致行为 |
| 两个答案都合格，但一个更合适 | 先定义偏好标准、检查标注一致性 | 有可靠成对偏好时考虑 preference learning |
| 多步工具任务经常中途走错 | 查状态、工具接口与轨迹 | 有可执行环境、有效奖励和预算时再考虑 RL |

监督微调（supervised fine-tuning, SFT）从示范回答中学习；偏好学习使用回答之间的比较；RL（reinforcement learning，强化学习）通过采样和奖励优化策略。这些方法可以有联系，例如 RLHF 也会使用偏好数据训练奖励模型，并不是互不相干的 3 档“升级”。先把目标定义清楚，才知道需要哪种数据和方法。

checkpoint 只是中间产物。若没保存 tokenizer、聊天模板和预处理版本，换台机器后，同一段对话可能已经不是同一组训练 token。若没有固定评估集，“第二次看起来更好”也很难复核。

这里说的可复现，首先是能重建数据、目标和评估协议，不保证不同硬件、库版本产生逐 bit 相同结果。PyTorch 的[复现说明](https://docs.pytorch.org/docs/2.8/notes/randomness.html)也明确区分这些条件。

## 对照实验尽量少改变量

第一轮只比较两种设置：原模型加现有提示，以及从同一份初始权重出发、用针对性示范做 SFT 后的模型。两者评估时使用相同的提示、资料和生成预算。这样更容易看清训练带来的变化。

这里固定的是初始 checkpoint 和比较条件，**不是冻结所有模型参数**。哪些参数更新，由全参微调或 LoRA 等方案决定。若同时换基座、加资料、改提示，就很难把效果变化归因到 SFT。

比较 LoRA 与全参微调时，也要记录两者的调参预算、实际 token、时间和资源。只写“都训练了 1 个 epoch”还不够：数据长度不同，计算量也会不同。

## 从哪里继续

按顺序读，就是一次小实验从选型到交付的过程。只想解决眼前的问题，也可以直接跳到对应一篇，不需要先学完所有分布式框架。

| 章节 | 这一步做什么 | 具体要取舍什么 |
| --- | --- | --- |
| [1 · 训练方案](training-plan.md) | 决定要不要 SFT，选择 LoRA / QLoRA / 全参方案及框架 | 行为问题是否值得训练，额外成本是否有必要 |
| [2 · 数据到 batch](data-pipeline.md) | 建记录、分组划分、套模板、检查 labels | 可追溯性、截断、padding 与 packing |
| [3 · 数据与目标](data-and-objectives.md) | 手算 mask 后的 loss，比较 token / 样本平均 | 监督哪些位置，长短样本各占多少权重 |
| [4 · 多卡选择](distributed-training.md) | 区分容量和速度问题，算 batch 与全局分母 | DDP / FSDP / ZeRO / TP / PP 的成本 |
| [5 · 保存与恢复](checkpoint-and-resume.md) | 跑一次中断恢复对照，区分 resume 与导出 | 存什么、何时存、换卡数后还能保证什么 |
| [6 · 实验与发布](experiments-and-release.md) | 比较新旧结果，沿请求排查错例，准备回滚 | 总体收益与分组回退；该改输入、训练还是评测 |

先看思路，可以读 1 → 2 → 6；准备实际动手，把 3 → 4 → 5 也跑通。两个 Python 标准库程序分别检查目标 / 评估，以及数据 / batch / 玩具恢复，不需要下载模型。接上真正的训练器后，还要验证 tokenizer、前向、梯度与分布式恢复，不能把教学程序跑通当作完整 SFT 已完成。

想先补算法，去 [SFT](../../05-post-training/sft-and-its-ceiling.md) 和 [RLHF 导读](../../05-post-training/rlhf/README.md)。那边讲优化方法，这边讲怎样知道自己究竟优化了什么。
