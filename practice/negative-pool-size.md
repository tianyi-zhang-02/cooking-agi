# 负样本池到底有多大

**中文** · [English](negative-pool-size.en.md)

> 阅读时间：约 8 分钟 · 类型：实践手记 · 最近审阅：2026-08

## 先用一句话讲清楚

对比学习说白了就是让模型做选择题。而在多卡训练里，很容易出现这么一件事：你以为自己在出 768 选 1 的难题，实际上每张卡都在做 32 选 1 的送分题——**而且不会有任何报错**。

## 先想一道选择题

假设我要教一个模型「什么内容适合推给这个用户」。

我手上有一条确认的正样本：用户 A 真的喜欢内容 X。怎么用它来训练？

最直接的办法是出一道选择题：给模型看用户 A，再给它一堆候选内容，其中一个是 X，其余都是随便抽来的。让它把 X 挑出来。挑对了就奖励，挑错了就惩罚。

那堆「随便抽来的」就是负样本。它们的数量，就是这道题的选项数。

现在关键的问题来了：**这道题有几个选项？**

- 4 选 1：模型答对了，你几乎学不到东西。瞎蒙都有 25% 正确率，而且四个选项里大概率有三个跟用户 A 八竿子打不着——它只需要分辨「这是不是同一个星球的东西」。
- 768 选 1：模型还能答对，那说明真本事。因为选项一多，里面必然混进几个**长得跟 X 很像、但其实不对**的内容，模型必须画出一条细得多的界线。

召回阶段面对的现实是后者：候选池里全是似是而非的东西。所以**训练时的选项数太少，就是在用送分题训练一个要去考难题的模型。**

这就是负样本池的意义。它不是一个「调一调可能有用」的超参，它直接决定了你这道题有多难。

## 于是那件容易出的事是这样

多卡训练里，框架会帮你把模型切开、分到每张卡上，梯度也会跨卡同步。这些都是配置项，打开就有。

但**出题是你自己在损失函数里写的**。框架不知道你的损失函数在干嘛，它不会主动把别的卡上的候选收集过来给你当干扰项。

结果就可能是：你有 24 张卡，每张卡的批大小是 32，你心里默认负样本池是 24×32=768。实际上每张卡只拿自己那 32 个样本互相当干扰项，题目是 32 选 1，不是 768 选 1。

| 东西 | 跨卡吗 | 谁负责 |
| --- | --- | --- |
| 参数 | 是，要用时 all-gather 拼回来 | 框架（分片策略一开就有） |
| 梯度 | 是，reduce-scatter 或 all-reduce | 框架 |
| 优化器状态 | 是，跟着参数一起切 | 框架 |
| 数据 | 是，每张卡拿自己那一份 | 框架 |
| **对比损失的负样本池** | **不一定** | **你自己，在 loss 里** |

前四行是配置，第五行不是。所以完全可能出现这个局面：模型状态在几十张卡上分片得漂漂亮亮、通信写得一丝不苟，而每张卡的对比损失只看得见自己那一小撮样本。

**这件事必须去损失函数的代码里确认，看训练配置是看不出来的。** 配置告诉你分片策略是什么，不告诉你分母里有几项。

## 把这道选择题写成公式

现在把上面那道题写下来。这就是 InfoNCE：

$$\mathcal{L} = -\log \frac{\exp\big(s(u, c^+)/\tau\big)}{\sum_{c \,\in\, \{c^+\} \cup \mathcal{N}} \exp\big(s(u, c)/\tau\big)}$$

每个符号是什么：

| 符号 | 意思 | 在代码里是什么 |
| --- | --- | --- |
| $u$ | 一次查询——这里就是「用户 A 当下的状态」 | 用户塔输出的那个向量 `z_u` |
| $c^+$ | 这道题的正确答案，确认过的正样本 | 正样本候选的向量 |
| $\mathcal{N}$ | 干扰项集合，也就是负样本池 | 分母里除正确答案外的所有候选 |
| $s(u,c)$ | 打分函数，双塔里就是两个向量的内积 | `z_u @ z_c` |
| $\tau$ | 温度，控制这个 softmax 有多「尖」 | 一个标量，越小越只关心最像的那几个 |
| 分母 | 所有选项的得分加起来 | **项数 = 选项总数 = $\lvert\mathcal{N}\rvert + 1$** |

这个式子读出来就是：**正确答案的得分，占所有选项得分总和的比例，越高越好。**

所以学习信号几乎全在分母那个求和里。分子只有一项，它自己说明不了任何事——只有跟一堆干扰项比起来它更高，才算学到了东西。

$\mathcal{N}$ 是本卡的批次，选项数就是 $B$；$\mathcal{N}$ 是全局的，就是 $N \times B$（$N$ 是卡数，$B$ 是每卡批大小）。

$N$ 是几十的时候，这中间差一个数量级以上。而这个改动**不需要新数据、不需要新标注、不改模型结构**——这类白捡的改动很少见，所以值得先去确认一遍你是不是正放着没用。

## 加跨卡聚合：一个几乎所有人第一次都会踩的坑

朴素的写法长这样：

```python
# 错的
z_all  = all_gather(z)                   # 把所有卡的候选向量收集过来
logits = z_u @ z_all.T / temperature     # 现在分母有 N*B 项了
loss   = cross_entropy(logits, labels)
```

看起来对：分母确实变成 $N \times B$ 项了。问题出在**通用的 all-gather 不带梯度**。

它把别的卡的张量搬过来了，但在本卡的计算图里，那些张量是常数——反向传播走到那儿就停了。

后果是梯度变得不对称：

| 谁 | 有没有梯度 | 意味着什么 |
| --- | --- | --- |
| 本卡的 `z_u` | 有 | 用户向量会被推离所有新增的干扰项 ✓ |
| 本卡的候选 | 有 | 正常更新 ✓ |
| **其他卡的候选** | **没有** | **它们不知道自己被当成干扰项了** ✗ |

对比学习本该是**互相推开**：用户向量离干扰项远一点，干扰项也离用户向量远一点。梯度断掉之后只剩前半句。

用选择题打比方：你把 4 选 1 改成了 768 选 1，学生选错会扣分——但那 764 个新加的干扰项，出题人从来不会因为「你写得太像正确答案」而被要求改题。题面变难了，可你只在半边施加了压力。

这个坑难受的地方在于**它看起来是work 的**：分母确实变大了，loss 数字确实变好看了，训练也确实在跑。指标可能还涨一点（因为用户塔那半边确实学到了）。你不会怀疑它。

两个修法：

1. 用**带 autograd 的** all-gather——各框架都提供了一个可微版本，名字一般在 `distributed.nn` 这类命名空间下；
2. 或者手动 gather 完之后，把本卡那一片**带着计算图** splice 回去：即把收集结果里属于本卡的那几行，换成原始的、有梯度的张量。

别靠读代码判断，直接测：

```python
z_all = gather(z)
g = torch.autograd.grad(loss, z_all, retain_graph=True)[0]
# 属于其它卡的那些行，梯度范数必须非零
assert g[other_rank_rows].norm() > 0
```

如果那部分是零，你就是在用一道更难的题，训一个感受不到难度的模型。

## 但它和采样修正是耦合的，得一起上

这一步最容易漏，而且漏了会往反方向走。

回到选择题的比方。干扰项是从哪儿来的？是从批次里其他样本的候选里借来的。而批次是从数据里随机抽的，**所以一个内容出现在批次里的概率，正比于它在数据里有多常见。**

热门内容本来就出现得多，于是它反复地、大量地出现在别人的干扰项里。模型被训练去「把干扰项的分数压下来」，而热门内容当干扰项当得最多，结果就是**模型学会了看到热门内容就压分**——这个偏置不是你设计的，是数据频率分布的副产品。

现在把池子扩大 $N$ 倍，这件事也跟着放大 $N$ 倍。

**跨卡聚合会把流行度偏置放大 $N$ 倍。**

标准的修正叫 logQ correction，在算分数的时候减掉采样概率的对数：

$$s'(u,c) = s(u,c) - \log Q(c)$$

| 符号 | 意思 | 怎么来的 |
| --- | --- | --- |
| $s(u,c)$ | 原始打分（两个向量的内积） | 模型算出来的 |
| $Q(c)$ | 候选 $c$ 出现在**一个批次**里的估计概率 | 流式频率估计就够，不用精确 |
| $-\log Q(c)$ | 越热门减得越多；长尾内容几乎不减 | 抵消「热门被当干扰项的次数多」 |
| $s'(u,c)$ | 修正后的分数，拿它进 softmax | 替换上面公式里的 $s$ |

为什么是**减 $\log Q$** 而不是别的？因为 softmax 是在对数空间里工作的，在对数空间减去 $\log Q$ 等价于在概率空间里除以 $Q$——也就是把「它是因为常见才被抽到」这部分除掉，还原成「如果均匀采样，它本该得几分」。

**结论是这两件事应该在同一个改动里落地。** 先上聚合、过一阵再补修正，中间那段时间训出来的模型带着一个被放大了 $N$ 倍、谁也没选过的先验，而离线指标不会告诉你——它只会显示召回涨了。

## 顺带：分片粒度也值得问一次

既然已经在翻分布式配置了，还有一个常见的错配。

**如果模型本身不大，把它切到所有卡上，是在为你根本不需要的显存付跨节点带宽。**

算一下就清楚：参数 + 梯度 + 优化器状态，一个 sub-1B 的模型在 bf16 加 Adam 下总共十几 GB，现代加速器单卡放得下。全局分片省的那点显存你压根不缺，代价却是每一层的 all-gather 都得跨节点走一趟。

节点内的互联比节点间快一个量级。「节点内分片、节点间复制」这种混合策略能把 all-gather 全压在节点内部，只让梯度同步跨节点——同样的显存预算，通信量差很多。

还有一条特别容易搞混的：**分片参数救不了激活。** 长上下文下真正吃显存的是前向存下来的中间张量，那是梯度检查点管的事，跟参数怎么切没关系。为了治激活爆显存而把分片开到最大，是在拧错的旋钮。

判据很简单：先把参数、梯度、优化器状态加起来，再跟单卡显存比一比。放得下，全局分片就是在买你不需要的东西。

## 落到检查清单

1. 我的对比损失，负样本池是本卡的还是全局的？——**去损失函数的代码里看，不要看训练配置**。
2. 如果是全局的，gather 带梯度吗？非本卡那些行的梯度范数是不是零？
3. 池子变大之后，采样修正跟上了吗？还是我刚把流行度偏置也放大了 $N$ 倍？
4. 我分片的这些东西，单卡到底放不放得下？
5. 真正吃显存的是参数还是激活？我拧的是对应那个的旋钮吗？
