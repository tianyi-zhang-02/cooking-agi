# 负样本池到底有多大

**中文** · [English](negative-pool-size.en.md)

> 阅读时间：约 6 分钟 · 类型：实践手记 · 最近审阅：2026-08

## 先用一句话讲清楚

在多卡训练里，「模型是分布式的」和「损失是分布式的」是两件事。参数、梯度、优化器状态可能全都跨卡分片了，而对比损失的负样本池还留在单卡本地——这个不对称**不报错**，只是让你以为自己的负样本数是卡数乘以批大小。

## 两个「分布式」不是同一个

| 东西 | 跨卡吗 | 谁负责 |
| --- | --- | --- |
| 参数 | 是，用时 all-gather 拼回 | 框架（分片策略一开就有） |
| 梯度 | 是，reduce-scatter 或 all-reduce | 框架 |
| 优化器状态 | 是，跟参数一起切 | 框架 |
| 数据 | 是，每张卡拿自己那一份 | 框架 |
| **对比损失的负样本池** | **不一定** | **你自己，在 loss 里** |

前四行是配置项，打开就有。第五行不是——框架不知道你的损失函数语义，它不会替你把别的卡上的向量收集过来。所以完全可能出现这种局面：模型状态在 N 张卡上均匀分片、通信写得很漂亮，而每张卡的对比损失只看得见自己那一小撮样本。

**这件事必须去损失函数的代码里确认，不能看训练配置。** 训练配置会告诉你分片策略是什么，不会告诉你分母里有几项。

## 为什么分母里有几项这么重要

对比损失的形状是这样的：

$$\mathcal{L} = -\log \frac{\exp(s(u, c^+)/\tau)}{\exp(s(u, c^+)/\tau) + \sum_{c^- \in \mathcal{N}} \exp(s(u, c^-)/\tau)}$$

学习信号几乎全在分母的那个求和里。$\mathcal{N}$ 是本卡的批次，负样本数就是 $B-1$；$\mathcal{N}$ 是全局的，就是 $NB-1$。

$N$ 是几十的时候，这是**一个数量级以上**的差别，而且不需要任何新数据、不需要新标注、不改模型结构。这类改动很少见，所以值得先去确认一遍你有没有白白放着。

直觉上：负样本越多，你越有机会在分母里放进「长得像但其实不对」的东西，模型被迫学出更细的边界。反过来，负样本太少时，随便一个不相关的候选就能把分母撑起来，模型学到的只是「区分开明显不同的东西」——这个能力在召回阶段几乎没用，因为候选池里全是长得差不多的。

## 加跨卡聚合：一个几乎所有人第一次都会踩的坑

朴素写法是这样：

```python
# 错的
z_all = all_gather(z)                    # 收集所有卡的候选向量
logits = z_u @ z_all.T / temperature
loss = cross_entropy(logits, labels)
```

问题是**通用的 all-gather 不带梯度**。它把别的卡的张量搬过来，但那些张量在本卡的计算图上是叶子节点、是常数。于是梯度只流回本卡那一片，其余 $N-1$ 卡贡献的负样本**推不动任何东西**。

现象非常有迷惑性：分母确实变大了，loss 数字确实变好看了，训练也确实在跑。但模型没有从新增的负样本里学到东西——它们只是把 loss 压低了一点，没有产生任何把它们推开的力。

两个修法：

1. 用**带 autograd** 的 all-gather（各框架都提供了一个可微版本，名字通常在 `distributed.nn` 这类命名空间下）；
2. 或者手动 gather 之后，把本卡那一片**带着计算图** splice 回去——即把 gather 结果里属于本卡的那一段，替换成原始的、有梯度的张量。

自检的办法比读代码可靠：

```python
z_all = gather(z)
g = torch.autograd.grad(loss, z_all, retain_graph=True)[0]
# 属于其它卡的那些行，梯度范数必须非零
assert g[other_rank_rows].norm() > 0
```

如果那部分是零，你就是在用一个更大的分母训一个没变的模型。

## 但它和采样修正是耦合的，必须一起上

这是最容易漏的一步。

批内负样本的采样分布**正比于内容频率**——一个内容出现在批次里的概率，取决于它在数据里有多常见。所以池子扩大 $N$ 倍，热门内容被当成负样本的次数也扩大 $N$ 倍。

**跨卡聚合会把流行度偏置放大 $N$ 倍。**

不做修正就上聚合，你会得到一个比之前更强、但方向仍然不是你选的 debias：模型系统性地压低热门内容的分数，幅度由数据频率分布决定，而不是由你决定。召回的整体数字可能还是涨的，但你已经引入了一个自己没设计过的先验，而且它比之前更大。

修正就是那条标准的 logQ：

$$s'(u,c) = s(u,c) - \log Q(c)$$

$Q(c)$ 是 $c$ 出现在批次里的估计概率，流式频率估计就够。展开见[正负样本到底该怎么定义](positive-negative-design.md)。

**结论是这两件事应该在同一个改动里落地**，不要分两次。先上聚合再补修正，中间那段时间你训出来的模型带着一个被放大的、没人选过的先验，而且离线指标不会告诉你。

## 顺带：分片粒度也值得问一次

既然已经在看分布式配置了，还有一个常见的错配。

如果模型本身不大，**把它切到所有卡上是在为你不需要的显存付跨节点带宽**。算一下就知道：参数 + 梯度 + 优化器状态，一个 sub-1B 的模型在 bf16 加 Adam 下总共十几 GB，现代加速器单卡放得下。全局分片省的那点显存你根本不需要，代价却是每一层的 all-gather 都要跨节点走。

节点内的互联比节点间快一个量级。「节点内分片、节点间复制」这种混合策略能把 all-gather 全压回节点内，只让梯度同步跨节点——同样的显存预算，通信量差很多。

还有一条更容易搞混的：**分片参数救不了激活。** 长上下文下真正吃显存的是前向存下来的中间张量，那是梯度检查点的事，跟参数怎么切没有关系。把分片开到最大来治激活爆显存，是在用错的旋钮。

判据很简单：先算参数+梯度+优化器状态的总量，再看它和单卡显存的关系。放得下，全局分片就是在买你不需要的东西。

## 落到检查清单

1. 我的对比损失，负样本池是本卡的还是全局的？——**去损失函数的代码里看，不要看训练配置**。
2. 如果是全局的，gather 带梯度吗？非本卡那部分的梯度范数是不是零？
3. 池子变大之后，采样修正跟上了吗？还是我刚把流行度偏置放大了 $N$ 倍？
4. 我分片的这些东西，单卡到底放不放得下？
5. 真正吃显存的是参数还是激活？我调的是对应那个的旋钮吗？
