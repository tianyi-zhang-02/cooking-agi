# 实践手记

> 阅读时间：约 3 分钟 · 类型：索引 · 最近审阅：2026-08

其他章节写的是「这个领域是怎么回事」，这里写的是**「我在真实系统里撞上了什么，以及后来怎么想的」**。

文体不同，所以单独放一个板块：教学章节可以从最干净的例子出发，实践手记必须从最脏的地方出发——数据是歪的、标签是猜的、离线涨了线上不涨。

## 这里的脱敏边界

这些笔记来自真实工作，所以边界必须是**写下来的规则**，不是每次临场判断。我漏过一次，所以有了这份清单。

**不写：**

- 公司名、产品名、团队名、同事名；
- 内部系统、服务、表、任务、代码库的名字；
- 数据规模、字段名、模型配置、超参、实验结果的具体数值；
- 项目时间线，以及任何能定位到具体组织决策的东西。

**同样不写，但最容易漏的——内部术语。**

数字和字段大家都记得删，词汇不会。把用户叫成某个特定的词、把某一层叫成某个特定的名字，**这些词本身就是指纹**，而且比数字更能定位：同行读一段就知道是哪家，甚至知道是哪个组。一份写着「不对应任何公司的字段和配置」的免责声明挡不住这个，因为泄漏发生在术语层，不在数据层。

所以：**所有专有名词一律换成领域通用说法。** 用户就叫用户，中间层就叫准实时层。

**只写：** 任何一个做同类系统的人都会遇到的问题、取舍，以及判断对错的依据。

**自检：** 把文章给一个做同类系统但不在这家公司的人看，问一句「你能说出这是哪家吗」。答得出来就还没脱干净。

## 笔记

### [离线涨了，线上不涨](offline-online-skew.md)

选择性观测 + 反馈闭环。为什么在日志上做的评估会系统性地高估一个会加剧该偏差的模型，以及为什么这件事**不能靠改损失函数解决**——只能靠让一部分曝光不由模型决定，并把倾向性记下来。

### [正负样本到底该怎么定义](positive-negative-design.md)

「没点」不等于「不喜欢」。四类样本的语义区分，以及一个大多数实现里都存在、但很少被承认的矛盾：口口声声说未观测不是负样本，训练时的 in-batch negative 恰恰在把它当负样本用。

### [从噪声反馈到可服务的检索系统](noise-to-signal-retrieval.md)

一份完整的系统设计笔记——signal construction、选择性视觉理解、对比式 post-training、发布门槛。比上面两篇长得多，是把整条链路串起来的那一篇。

## 这些笔记想回答的共同问题

```text
我拿到的标签，和我想优化的东西，差在哪里？
这个差距是随机的，还是被旧策略系统性地造出来的？
我的评估集，是不是也来自同一个被污染的分布？
```

前两个问题决定模型能学到什么，第三个决定你能不能发现前两个出了问题。
