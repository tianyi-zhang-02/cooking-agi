## 不只看架构图

每篇尽量讲清四件事：

1. **问题是什么。** 先交代任务和约束，把观察到的事实与猜测分开。
2. **为什么这样选。** 比较可选方案，也说清放弃了什么。
3. **模块怎么配合。** 顺着数据流看代码，弄清每一步拿到什么、交出什么。
4. **怎么知道有效。** 给出验证方法；教学例子和真实测量分开写。

一个定位清楚的 bug、一次排除错误假设的实验，也值得记录。没有明显提升，不代表没有学到东西。
